# Decisions and documented deviations

| Decision | Reason | Alternatives considered |
|---|---|---|
| Use Firestore as the only persistent application store; store PDF/JSON blobs as chunk documents. | This is an explicit architecture constraint. It keeps the backend as the only file/data access boundary and avoids any object-storage dependency. | Cloud Storage, another database, local persistent files — rejected for this phase. |
| Use 512 KiB chunks and eight-chunk writes by default, with a 9 MiB raw payload guard. | Leaves room below Firestore's 1 MiB document and 10 MiB API request limits for Firestore encoding and request overhead. Chunk writes remain far below the documented 500-write batch limit. | Larger chunks/batches reduce writes but raise document/index/request risk; smaller chunks multiply reads/writes. |
| Exclude `chunks.data` from single-field indexing. | Chunk bytes are never queried; indexing them adds storage/write work without query value. | Default automatic indexing — rejected. |
| Render PDF pages to PNG data URLs and send them to NVIDIA NIM's chat completions API; persist only the final validated JSON report. | This model's vision endpoint accepts image inputs, while PDF pages can be rendered locally with PyMuPDF. It avoids provider-side file lifecycle management and excludes reasoning text from the immutable artifact. | Send raw PDF bytes or persist the full reasoning completion — rejected. |
| Preserve the existing `roof_data.json` and extraction script, and align the API extraction prompt with its explicit report schema. | The repo already has a machine-readable sample and field-by-field extraction instructions; the API uses inline PDF bytes and the same output shape so normalization and the fixture stay compatible. | Introduce a different response shape or overwrite the fixture — rejected. |
| Use NVIDIA NIM for model-backed measurements and diagram facet points, with independent PyMuPDF checks during geometry review. | The app needs candidate points that its geometry workflow can consume. NVIDIA coordinates stay low-confidence and require review; deterministic vector analysis supplies scale and comparison evidence. Roofr scalar measurements continue to use the local report parser. | Treat model coordinates as approved geometry — rejected because they need page-frame, area, pitch, and topology review. |
| Preserve Roofr flat/pitched totals, areas-by-pitch, and display-rounded facet labels as separate fields. | The PDF reports 643 SF pitched and 515 SF flat, while rounded pitch groups total 1,159 SF and do not reconcile with those system totals. Each facet label is rounded and the labels sum to 1,163 SF. | Recalculate, merge, or force the source groupings to reconcile — rejected because it would replace reported values with assumptions. |
| Run a calibrated Roofr adapter and keep its partial geometry `needs_review`; approval never happens during extraction. | The PDF supports eight area and pitch labels, six arrows, and a six-plane candidate, but two directions are missing and shared-edge height constraints conflict. Area and length checks alone do not prove topology or heights. | Infer missing arrows/heights from the predominant pitch or area totals — rejected as invented geometry. |
| Treat Roof Manager as partially outlined evidence and keep it `needs_review`. | Page 3 produces 21 closed candidates versus 31 reported planes; dimension labels have 25/60 inliers, three edge totals exceed tolerance, and no per-plane pitch/direction is reported. The aggregate 8:12 area match is only a hypothesis check. | Set every plane to 8:12 or complete a 31-plane mesh from aggregate data — rejected because constraints do not support it. |
| Keep the geometry schema at version 1.1 and reuse it for extracted and manual-review candidates. | The existing vertices, planes, edges, confidence, compass, and estimated-height fields represent page-derived and contractor-edited data without changing the demo fixture contract. | Add a new schema version or translate the demo fixture — unnecessary for the current fields. |
| Use NVIDIA diagram points as editable candidates, then apply per-page PyMuPDF scale calibration, topology checks, and explicit review versions. | NVIDIA's page-point estimates are useful as input to the app, while PDF vectors and dimension labels provide independent checks. Points remain unapproved until a person reviews them. | Treat model-generated vertices as final geometry — rejected because point estimates need page-frame, area, pitch, and topology review. |
| Store candidate geometry inline below the configured limit, otherwise as a chunked Firestore artifact. | Geometry versions use the existing storage helper and Firestore-only file store. Report PNGs are rendered from verified chunks to temporary files on demand. | Persist page images or large geometry in Cloud Storage — rejected by the Firestore-only rule. |
| Require edits to create an immutable revision and rerun topology, heights, and validation server-side. | Browser coordinates, pitches, directions, and stack order are untrusted. Optimistic concurrency protects the current pointer; approved versions remain immutable and approval requires explicit confirmation. | Accept client-computed heights, mutate an approved record, or auto-approve a fit — rejected. |
| Bundle a six-surface demo geometry fixture ported from `roof3d.html`; label it `DEMO` and keep it out of customer geometry storage. | The reference provides explicit illustrative plan points and pitch-derived heights that can exercise the viewer's per-plane controls. Its absolute elevations are estimated, two 18/12 SF sliver areas are omitted, and its area deltas do not validate a property reconstruction. | Treat the fixture as extracted/approved Roofr geometry or write it to a project geometry version — rejected. |
| Preserve the page coordinate frame and compass instead of rotating the diagram north-up. | The Roofr Diagram compass places north left, east up, south right, and west down. The source viewer defines `u` right, `v` up, and maps three.js to X=`u`, Y=`h`, Z=`-v`. | Rotate to conventional north-up — rejected because it would no longer match the report diagram. |
| Use the existing root report `83 Rue Falardeau, Gatineau, QC J8X 3E1.pdf` because the addendum's alternate filename `roofr_83_rue_falardeau.pdf` is absent. | The address-named supplied report is the eight-page Roofr report documented in `PDF_ANALYSIS.md`; its text and diagrams match the stated measurements. | Stop for the missing alias — unnecessary because the actual supplied report is present. |
| Use the repository-root `roof3d.html` reference because `fixtures/reference/roof3d.html` is absent. | The root file contains the specified hand-built plan coordinates, heights, and facet logic; it was read in full and is the source used by the bundled demo fixture. | Stop for the missing copy or recreate its geometry from memory — unnecessary and less reliable. |
| Require an explicit flat roofing system and user-supplied coverage, laps, package size, and price. | The Roofr report excludes its 515 SF flat area from pitched-material calculations and does not specify EPDM/TPO/PVC/modified-bitumen configuration or price. | Use asphalt shingles or assume typical membrane coverage on the flat system — rejected. |
| Leave the Quote tab as a clear placeholder while no quote API/PDF generator exists. | This PDF-support update extends measurement review and estimates; existing code has no quote generation or artifact-download endpoint. | Display a fake generated quote or claim a PDF is available — rejected. |
| Use an in-process FastAPI background task backed by Firestore job documents for Milestone 1. | It is the smallest persistent-job implementation that returns immediately and supports local work. | Add a separate distributed queue now — deferred; Firestore remains persistence, but a multi-instance worker/lease model is needed before scaling. |
| Use an application-local responsive component style layer rather than adding shadcn/ui in this milestone. | There was no existing component library. A cohesive custom style layer keeps the first milestone focused while preserving a consistent visual system. | Add shadcn/ui or a full third-party component library — deferred. This is a deliberate deviation from the suggested default and can be revisited. |
| Store money as decimal strings in Firestore and calculate with Python `Decimal`. | Firestore has no decimal type; strings preserve exact decimal values and JSON interoperability. | Float persistence — rejected due to rounding risk; integer cents is also valid but would require a separate currency scale conversion. |
| Treat a source quantity discrepancy greater than one purchase unit as a warning; mark unsupported conversion/package assumptions as incomplete pricing. | The PDF rounds source measurements to integers, while the app keeps decimal quantities internally. No total should imply a configured price for an unknown package or conversion. | Silently use source “with waste” quantities or charge them as another unit — rejected. |
| Show only approved project geometry in the 3D tab; keep the demo separately labelled when no approved version exists. | The project remains useful as an estimator while candidates are reviewed. A PDF-derived shape is not presented as the customer's roof until checks pass and the user approves it. | Display an unapproved candidate as the property roof or silently substitute the demo — rejected. |
| Keep quote PDF generation unimplemented and explicit in the Quote tab. | Geometry approval and estimator updates do not implement the separate quote/artifact workflow. | Present an estimate snapshot as a downloadable customer quote — rejected. |
| Pin Next.js 16.4.2 with React 19.3.0. | The [official October 14, 2026 security advisory](https://nextjs.org/blog/nextjs-security-update-october-14-2026) lists 16.4.1 as the patched 16.4 release; the selected 16.4.2 is newer, and the [16.x line is active LTS](https://nextjs.org/support-policy). | Keep the earlier 16.2 pin — rejected because it predates the security update. |
| Do not add a Python virtual-environment prerequisite. | The repository commands install into the selected Python installation; no `.venv` is required. | Repository-local Python environment — removed from setup. |
| Declare Python 3.11–3.14 as the supported API range. | The selected [PyMuPDF release](https://pypi.org/project/PyMuPDF/1.27.2/) publishes wheels through CPython 3.14; CPython 3.15 is not listed as supported by the package. The repository's local Python 3.15 runtime therefore cannot be treated as a verified API environment. | Claim 3.15 support without a documented PyMuPDF wheel/runtime — rejected. |
| Keep Firebase Admin as the required auth/Firestore SDK even though its Python distribution installs `google-cloud-storage` transitively. | The SDK distribution declares that package as a dependency; the repository has no direct dependency, import, bucket configuration, Storage API call, or persisted data in Cloud Storage. The repository policy scanner checks authored source/configuration and direct dependencies. | Drop Firebase Admin or falsify its dependency metadata — rejected because that would conflict with the requested SDK and produce an unsupported install. This transitive package is an explicit ecosystem caveat, not an application storage path. |
| Pin React Three Fiber 9.8.1 alongside React 19.3.0. | Fiber 9.8.1's package metadata supports React/React DOM `<19.4`; 9.5.0 rejected 19.3.0 during normal npm peer resolution. See the [pinned Fiber metadata](https://github.com/pmndrs/react-three-fiber/blob/v9.8.1/packages/fiber/package.json). | Force-install peer-incompatible versions or downgrade React — rejected. |
| Use Next's webpack production build command in the package script. | The default Turbopack build could not start a local worker in this managed environment, while the same app compiled and prerendered successfully with Next's supported webpack build. Pinning the compiler makes the documented `npm run build` command reproducible here. | Leave Next's default compiler selection — rejected for this workspace because its production build could not complete. |
| Use Google anonymous credentials only when the Firestore emulator host is configured and no service-account path is supplied. | The Firestore emulator does not require OAuth, and local development should not depend on real Admin credentials. Real Firebase access continues to require explicit credentials or ADC. | Require ADC for local emulation — rejected because it prevented the configured local emulator from serving the app. |

## Verified external limits

The official Firestore quota page documents 1 MiB maximum document size and a 10 MiB maximum API request size. Firebase's batch-write docs describe batches and its SDK reference documents a 500-write maximum. The implementation chooses much smaller write batches. See [Firestore quotas](https://firebase.google.com/docs/firestore/quotas), [transactions and batched writes](https://firebase.google.com/docs/firestore/manage-data/transactions), and [Firestore pricing](https://firebase.google.com/docs/firestore/pricing).
